## 2. Key Architecture & Design Decisions

### Z80 Structure Layout (`Z80.pbi` / `translate.py`)
- **Index Register Mapping (`XX`)**: To enable simple translation of `IX`/`IY` prefix handlers, the union structure `XX` was added as a first-class member of the `Z80` structure.
  - At the start of `CodesDD`, `*R\XX\W = *R\IX\W`. At the end, `*R\IX\W = *R\XX\W`.
  - This completely avoids macro parameter expansion issues inside the autogenerated blocks.

### Macro Parentheses Call Conventions
- Parameterless macros (e.g. `M_CALL`, `M_JP`, `M_JR`, `M_RET`) are defined without parentheses in `Z80.pbi` (`Macro M_CALL` ... `EndMacro`) to align with C-style references which do not require `()` for invocation.

### Parser & Translation Pipeline Constraints
If you modify `translate.py`, remember these critical translation constraints:
1. **Inequality and NOT mapping**: `!=` must be replaced with `<>` and logical `!` with ` Not ` before other bitwise operators are parsed, so that bitwise XOR `!` (which translates from C `^`) is not corrupted.
2. **Nesting-Aware Parenthesis Parser (`replace_c_ifs`)**: Do not use regex to parse general C `if` conditions, because nested parentheses (e.g., `if(!(AF & Z_FLAG))`) cause regex groups to truncate early. Use the stack-based parenthesis matching function `replace_c_ifs` instead.
3. **C continuation lines**: C allows splitting long statements across lines. The preprocess block in `process_file` merges any lines ending with standard continuation characters (like `|`, `&`, `+`, `-`, `=`, `,`, `(`, `?`, `:`) to ensure statement integrity on single lines.

### Motherboard and Peripheral Mappings (`MSX.pbi`)
- **Callback Prefixing**: To prevent compiler errors with the Z80 prototype global variables `RdZ80`, `WrZ80`, etc., the callback procedures in `MSX.pbi` are prefixed with `MSX` (e.g., `MSXRdZ80`, `MSXWrZ80`). They are mapped to the Z80 pointer variables at runtime (`RdZ80 = @MSXRdZ80()`).
- **Intel 8255 PPI & Matrix Row Reads**: The matrix rows are selected by the lower 4 bits of `PPI\Rout[2]` (Port C Output). Port C must be configured as Output (by writing `$82` to Control Register Port `$AB`) before `Rout[2]` updates with values written to Port `$AA`.
- **64-bit OS File Handle Safety**: When using `#PB_Any` with file loading routines like `ReadFile`, the returned file ID must be stored in `.i` (Integer) variables rather than `.l` (Long) to prevent truncation and debugger crashes.
- **Scanline & Interrupt Timer (`MSXLoopZ80`)**: Handled by dividing scanline execution into active display and HBlank phases using CPU cycles mapping based on the 3.57MHz MSX master clock. Intercepts VBlank and line coincidence boundaries, calls `SetIRQ` to flag Z80 interrupt lines, and triggers handler diversions.
